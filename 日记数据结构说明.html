日记数据结构完整文档

📊 整体架构

你的日记系统采用分层 ETL 架构，数据经历以下处理阶段：

原始数据 (Raw) 
  ↓
基础计算字段 (_meta_) 
  ↓
AI 深度提取字段 (_ai_meta)
  ↓
最终增强记录

📝 Layer 0: 原始数据字段 (Raw Data)

这些字段来自数据库存储，在整个系统生命周期中保持不变。

字段名 类型 含义 边界/约束
_id String 唯一记录ID 必有，由前端或数据库生成
time String (ISO 8601) 记录的时间戳 必有，格式如 2023-11-23T09:30:00
ganshou String (HTML) 日记内容/感受 HTML 格式，可包含标签，最多可延伸至数千字符
tiyan String 体验/感受标签 如: 心流, 疲惫, 焦虑 等情绪词
xinqing String (HEX Color) 心情颜色代码 16进制颜色，如 #FF0000(红), #FFFF00(黄) 等
shanggexiangmu String 项目/类别名称 如: Project A, 学习, 生活琐事
chixushijian String 持续时间 格式如 1小时30分, 0时23分, 2小时
chengjiu Boolean 是否有成就/完成 true / false，可空

原始数据示例

{
  "_id": "1700715000000_项目A_今天进展顺利",
  "time": "2023-11-23T09:30:00",
  "ganshou": "<p>今天进展顺利，完成了三个需求，团队合作愉快。</p>",
  "tiyan": "心流",
  "xinqing": "#FFFF00",
  "shanggexiangmu": "项目A",
  "chixushijian": "1小时30分",
  "chengjiu": true
}

🔧 Layer 1: 计算元数据字段 (meta)

由 simpleEnrichers.js 在数据加载时 自动生成，不依赖 LLM，基于确定性规则计算。

1.1 时间维度 (Time Dimension)

字段名 类型 含义 范围/示例
_meta_timestamp Number Unix 时间戳（毫秒） e.g., 1700715000000
_meta_year Number 年份 e.g., 2023
_meta_month Number 月份 1-12
_meta_day Number 日期 1-31
_meta_hour Number 小时 0-23
_meta_weekday String 星期几 周一, 周二, ..., 周日
_meta_is_weekend Boolean 是否周末 true / false
_meta_time_range String 时间段 上午 (6-12), 中午 (12-14), 下午 (14-18), 晚上 (18-23), 深夜 (23-6)

计算规则：

  • 从 time 字段的 ISO 8601 字符串解析
  • 周末判定：JavaScript 的 getDay() 返回 0 或 6

1.2 行为维度 (Behavior Dimension)

字段名 类型 含义 边界/规则
_meta_duration_min Number 持续时间（分钟） >=0，通过解析 chixushijian 字段获得
_meta_project String 项目规范化名称 默认值 未分类（若 shanggexiangmu 为空）
_meta_has_achievement Boolean 是否有成就 chengjiu === true

解析规则（时间）：

"1小时30分" → 90分钟
"2小时" → 120分钟
"45分" → 45分钟
"0时23分" → 23分钟
"" → 0分钟（无效值）

1.3 内容维度 (Content Dimension)

字段名 类型 含义 边界/约束
_meta_plain_text String 纯文本内容 HTML 标签已去除
_meta_text_length Number 文本长度（字符数） >=0

处理规则：

  • 从 ganshou 的 HTML 中去除所有标签
  • 统计纯文本的字符数

1.4 情绪维度 (Emotion Dimension)

字段名 类型 含义 范围/边界
_meta_mood_score Number 情绪分值 -2.0 ~ +2.0（闭区间）
_meta_emotion_raw String 原始情绪标签 来自 tiyan 字段，默认 常规

计算规则（复合打分）：

  1. 从 tiyan 词汇打分：

    • 积极词：心流, 愉快, 开心, 顺利, 高兴, 满意, 成功, 棒 → 各 +0.5
    • 消极词：疲惫, 焦虑, 烦躁, 沮丧, 糟糕, 失败, 崩溃, 难过 → 各 -0.5

  2. 从 xinqing 颜色映射：

    {
  '#FF0000': -2,    // 红色 = 极度消极
  '#FFA500': -1,    // 橙色 = 消极
  '#FFFF00':  1,    // 黄色 = 积极
  '#90EE90':  0.5,  // 浅绿 = 微弱积极
  '#87CEEB': -0.5,  // 浅蓝 = 微弱消极
  '#9370DB':  2,    // 紫色 = 极度积极
  '#FFFFFF':  0     // 白色 = 中立
}

  3. 最终分值：

    • 总和 = tiyan 各词打分 + xinqing 颜色值
    • 约束到 [-2, +2] 范围内

示例：

  • tiyan="心流" + xinqing="#FFFF00" → 0.5 + 1 = 1.5 ✅
  • tiyan="焦虑疲惫" + xinqing="#FF0000" → -1.0 + (-2) = -3 → 约束到 -2 ⚠️

1.5 辅助字段 (Utility Fields)

字段名 类型 含义
_meta_id String 标准化 ID（可用于 SQL 关联）
_meta_created_at String 元数据生成时间戳

🧠 Layer 2: AI 元数据字段 (_ai_meta)

由 llmEnricher.js 通过大模型 按需深度提取（缓存机制），基于 五层模型 组织。

2.1 计算机制

  1. Hash 计算： 对记录的内容、项目、时间生成 MD5 Hash
  2. 缓存检查： 查询本地缓存文件 ai_meta_index.json
  3. 增量处理： 只对新记录或强制刷新的记录调用 LLM
  4. 结果保存： AI 响应缓存在本地，避免重复 API 调用

2.2 Schema 定义（五层模型）

🌍 Layer 1: 物理世界 (Physical Reality)

字段名 类型 含义 约束
location String 物理地点 如: 办公室, 家中卧室, 咖啡馆, 通勤地铁
items Array 涉及的具体实体 书名、电影、食物、工具等，严禁统称
people_involved Array 社交图谱中的人物 如: 导师, 朋友小王, 父亲
interaction_type Enum 交互模式 Solo / OneOnOne / Group / Crowd
interaction_detail String 交互具体性质 如: 深度对谈, 争吵, 单向输出, 协同工作

示例：

{
  location: "团队会议室",
  items: ["白板", "MacBook Pro", "咖啡"],
  people_involved: ["导师张教授", "小李", "项目经理"],
  interaction_type: "Group",
  interaction_detail: "讨论项目需求，有分歧但理性沟通"
}

🎯 Layer 2: 行为与分类 (Action & Taxonomy)

字段名 类型 含义 枚举值
main_action String 核心行为摘述 自由文本，如 反思学业挫折, 完成代码审查
content_type Enum 内容体裁 DailyLog / Reflection / Letter / Idea / Dream
primary_domain Enum 生活重心领域 Career / Academic / Relationship / Health / Entertainment / PersonalGrowth / LifeLog

字段含义：

  • DailyLog: 流水账式日记，记录日常事件
  • Reflection: 深度反思，包含思考和感悟
  • Letter: 写给某人的信，通常有心理边界
  • Idea: 灵感记录，碎片化思想
  • Dream: 梦境记录

💪 Layer 3: 能量与心流 (Energy & Flow)

字段名 类型 含义 范围/约束
mood_tags Array 精细化情绪标签 使用标准情绪词库的词汇，可多标签
energy_level Number 综合电量 1-10 (1=极度疲惫, 10=充满活力)
focus_level Number 专注度/心流深度 1-10 (1=涣散分心, 10=物我两忘)
physiological_sensations Array 具体生理感受 如: 头痛, 胸闷, 轻盈, 有力
physiological_valence Enum 生理状态评价 Positive / Negative / Neutral / Mixed
root_cause String 情绪与状态的直接归因 如: 学业受挫, 成功完成项目

标准情绪词库（用于 mood_tags）：

积极正向:
  - 狂喜, 振奋, 激动, 热血, 自豪, 成就感, 惊艳, 痛快
  - 沉浸, 心流, 专注, 充实, 通透, 启发, 好奇, 兴致勃勃
  - 放松, 安心, 惬意, 满足, 治愈, 确幸, 温暖, 舒适, 慵懒

消极负向:
  - 愤怒, 烦躁, 暴躁, 不满, 厌恶, 鄙视, 抗拒, 不耐烦
  - 憋屈, 委屈, 无奈, 挫败, 无力感, 心累, 受挫, 气馁
  - 难过, 失望, 沮丧, 低落, 孤独, 空虚, 怅然, 心碎, 遗憾
  - 焦虑, 不安, 担忧, 恐慌, 心慌, 紧张, 压力山大, 畏难

社交关系:
  - 社恐, 局促, 尴尬, 被理解, 被忽视, 感激, 羡慕, 防备, 坚定, 硬气

复杂微妙:
  - 纠结, 矛盾, 拉扯, 释然, 和解, 怀旧, 五味杂陈, 如释重负, 意犹未尽

中性状态:
  - 平静, 平淡, 放空, 无聊, 麻木, 迷茫, 犹豫, 清醒, 观察

生理心理:
  - 疲惫, 昏沉, 紧绷, 窒息感, 瑟缩, 饥渴, 舒展

🧠 Layer 4: 认知与心理 (Cognition & Psychology)

字段名 类型 含义 范围/约束
agency_level Number | null 掌控感评分 -5 ~ 5 (null 若信息不足)
time_orientation Enum | null 时空取向 Past / Present / Future / Timeless / null
maslow_need String | null 核心需求层级 如: 生理需求, 安全感, 爱与归属, 自我实现 / null
thinking_patterns Array | null 思维模式识别 包含非理性信念或 ["Rational"] / null

maslow_need 参考值：

生理需求 → 食物、睡眠、休息
安全感 → 稳定性、预测性、有序感
爱与归属 → 社交、被认可、亲密关系
尊重与认可 → 成就、地位、自尊
认知需求 → 学习、理解、探索
审美需求 → 美感、设计、和谐
自我实现 → 成长、达成目标、发挥潜能
超自我实现 → 帮助他人、改变世界

thinking_patterns 认知扭曲列表：

非黑即白 → 事物非此即彼，无中间态
灾难化思维 → "最坏情况一定会发生"
过度概括 → 由单次事件推断普遍规律
贴标签 → "我是个失败者"
应该思维 → "我必须..."
情绪化推理 → 用感受代替事实
心理过滤 → 只关注消极方面
读心术 → 臆断他人想法
无 → （无法判定）
理性客观 → （信息充分且思维理性）

💎 Layer 5: 资产与沉淀 (Assets & Output)

字段名 类型 含义 约束
summary String 一句话摘要 格式: Who + Do + Context
key_quotes Array 智慧资产/金句 直接从文本中摘录
next_steps Array 待办事项/Open Loops 文中明确提到的下一步
content_depth Enum 信息密度评级 shallow / normal / deep

content_depth 定义：

  • shallow: 流水账、极短、无深度思考
  • normal: 有基本描述、叙述清晰
  • deep: 有深度思考、详细记录、多维度分析

🛡️ 数据边界与约束

字段长度限制

字段 最大长度 备注
ganshou (HTML) 无硬限制 实际上可容纳数千字符，前端编辑器无限制
_meta_plain_text 同 ganshou 去除 HTML 后的纯文本
shanggexiangmu 100 字符 项目名应简洁
tiyan 50 字符 情绪标签通常 1-5 个词
summary (_ai_meta) 200 字符 LLM 提取的摘要

时间相关约束

约束 说明
time 格式 必须是有效的 ISO 8601 字符串，如 2023-11-23T09:30:00
_meta_hour 0-23（24 小时制）
_meta_month 1-12
_meta_day 1-31（根据月份调整）

数值约束

字段 范围 说明
_meta_mood_score -2.0 ~ +2.0 被约束到此区间
_meta_duration_min >= 0 负数无效
energy_level 1-10 必须为整数
focus_level 1-10 必须为整数
agency_level -5 ~ 5 或 null 可为 null

枚举约束

字段 允许值
content_type DailyLog | Reflection | Letter | Idea | Dream
primary_domain Career | Academic | Relationship | Health | Entertainment | PersonalGrowth | LifeLog
interaction_type Solo | OneOnOne | Group | Crowd
physiological_valence Positive | Negative | Neutral | Mixed
time_orientation Past | Present | Future | Timeless
content_depth shallow | normal | deep

数据有效性规则

  1. 必填字段（原始数据）：

    • time, _id, ganshou 至少存在一个

  2. Layer 1 (meta) 字段：

    • 自动生成，始终有效值（通过默认值确保）

  3. Layer 2 (_ai_meta) 字段：

    • 可为 null（表示未处理或处理失败）
    • summary, content_type, primary_domain, mood_tags, agency_level, focus_level 是必填的（当 _ai_meta 非 null 时）
    • agency_level, time_orientation, maslow_need, thinking_patterns 可为 null（当信息不足时）

  4. 数组字段（_ai_meta）：

    • items, people_involved, mood_tags, physiological_sensations, key_quotes, next_steps, thinking_patterns 均可为空数组 []
    • 当为 null 时表示未处理

🔄 数据流转全流程

1. 用户在前端编辑日记
   ↓
2. 前端发送原始数据（_id, time, ganshou, tiyan, xinqing, shanggexiangmu, chixushijian, chengjiu）
   ↓
3. 后端 dataLoader.js 加载数据
   ↓
4. 使用 simpleEnrichers.js 生成 _meta_* 字段（确定性 ETL）
   ↓
5. 使用 llmEnricher.js 查询缓存或调用 LLM 生成 _ai_meta 字段（增量 ETL）
   ↓
6. 保存到 appData.json（仅原始字段）+ ai_meta_index.json（AI 缓存）
   ↓
7. 查询时合并：原始字段 + _meta_* + _ai_meta
   ↓
8. 前端渲染增强的日记卡片

📊 数据统计与分析

SQL 分析维度（基于 meta）

  • 按项目统计： 使用 _meta_project
  • 按时间统计： 使用 _meta_timestamp, _meta_year, _meta_month, _meta_weekday, _meta_time_range
  • 情绪分析： 使用 _meta_mood_score, _meta_emotion_raw
  • 效率分析： 使用 _meta_duration_min, _meta_has_achievement
  • 内容分析： 使用 _meta_text_length, _meta_plain_text

向量搜索维度（基于 _ai_meta）

  • 语义检索： 综合使用 summary, mood_tags, items, people_involved, main_action 等字段
  • 情绪搜索： 通过 mood_tags 和 root_cause
  • 主题搜索： 通过 primary_domain, content_type

🔍 数据访问示例

查询特定时间范围的记录

const records = data.filter(r => 
  r._meta_month === 11 && r._meta_year === 2023
);

查询高能量且高专注的记录

const focused = data.filter(r =>
  r._ai_meta?.energy_level >= 8 &&
  r._ai_meta?.focus_level >= 8
);

计算平均情绪分值

const avgMood = data.reduce((sum, r) => sum + r._meta_mood_score, 0) / data.length;

按项目分组统计

const byProject = {};
data.forEach(r => {
  if (!byProject[r._meta_project]) {
    byProject[r._meta_project] = { count: 0, totalHours: 0, avgMood: 0 };
  }
  byProject[r._meta_project].count++;
  byProject[r._meta_project].totalHours += r._meta_duration_min / 60;
  byProject[r._meta_project].avgMood += r._meta_mood_score;
});

⚠️ 常见注意事项

  1. 原始字段不可变： 修改原始字段后，相应的 meta 字段需要重新计算
  2. AI 缓存失效： 若修改了 ganshou, tiyan, time, shanggexiangmu，需强制刷新 _ai_meta
  3. 颜色与情绪的映射可调： 若要调整 xinqing 的颜色值分数，修改 simpleEnrichers.js 中的 colorMap
  4. LLM 成本控制： 每个新记录都会消耗 API 额度，建议定期检查缓存文件大小
